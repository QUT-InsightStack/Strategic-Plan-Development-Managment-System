# Management report master

The **Reports & Summary** tab of the Management Dashboard (`/management-dashboard?tab=reports`) shows one fixed report template. The backend decides which sections and which rows each user receives; the frontend only renders and exports the result. It replaces the previous list of nine report datasets.

## Sections

| # | Section | Required permission | Content |
|---|---|---|---|
| 0 | Report Information (cover) | — | Title, planning period, generated by / at, applied filters, data-scope statement, omitted sections, contents |
| 1 | Executive Summary | `strategic_records.view` | The six dashboard KPIs |
| 2 | Plan Status | `strategic_records.view` | Plan register with lifecycle label (`planning_status_label`) and approval status |
| 3 | Objective Progress | `strategic_objectives.view` | Objectives in approved plans, grouped by plan and sorted by PDP chapter: progress %, status, overdue flag, office, last update |
| 4 | Strategic Alignment | `strategic_objectives.view` | Agenda, PDP chapter, objective, responsible office, missing links |
| 5 | Office / Unit Performance | `strategic_objectives.view` | Per unit: objectives, completion %, alignment %, inputs submitted / pending (only with input access), overdue |
| 6 | Inputs & Consolidation | `implementation_inputs.view` or `implementation_inputs.view_all` | Submitted inputs and per-office consolidation, in the existing input scope |
| 7 | Approvals | `strategic_records.view` | Plan approval status; **My approval decisions** only for users who have acted in an approval workflow |
| 8 | Overdue Items | `strategic_objectives.view` | Incomplete objectives in approved plans after the plan end date |
| 9 | Annex: Definitions | — | Status, overdue, alignment coverage, returned = rejected, scope |

A section the user cannot access is not returned at all. The cover lists it under "Sections not included" so it is not read as zero. Inside the Executive Summary, a KPI that needs a missing permission shows "No access". Section 6 is also omitted when the account has input permission but no input scope (for example, an Office account without an active unit).

Rules are the existing ones: Overdue = incomplete after the plan end date (no at-risk threshold); Returned for correction = the existing `rejected` approval status; input statuses Pending review / Accepted / Declined. No statuses or schema were added for the report.

## Data scope and filters

- Plans: `StrategicPlanAuthorizationService::authorizedPlanIdsForListing` (draft and finished plans), as in `GET /api/strategic-plans`.
- Objectives: the same query as `GET /api/strategic-objectives`, including `scopeObjectivesForUser`; archived objectives are excluded.
- Inputs: `ImplementationInputQueryService::reportInputs`, the same scoped query as `GET /api/implementation-inputs`.
- My approval decisions: `plan_workflow_history` rows where the user is the actor with an `approved` / `rejected` action, for plans in the filtered scope.

The report takes the dashboard's shared filters (`plan_id`, `period` such as `2023-2028`, `office`, `status` as `plan:<status>` or `objective:<status>`, `approval_status`). Filtering follows the dashboard's `filterManagementRows` rules, implemented again in `ManagementReportService`, so the figures match the dashboard. The dashboard tabs still calculate in the browser; the report calculates on the server.

## API

- `GET /api/management/reports/master` — requires `reports.view`. Returns `{ meta, sections[], omitted_sections[] }`. Each section has `id`, `number`, `title`, `description` and, depending on the section, `fields` (cover), `kpis`, `tables[]` (`id`, `title`, `columns[{key,label}]`, `rows[]`, optional `group_by`) or `definitions[]`.
- `GET /api/management/reports/master/export?format=csv&section=<id>[&table=<id>]` plus the same filters — requires `reports.view` and `reports.export`. Returns one section table as a UTF-8 CSV (with BOM). Every cell is quoted, and cells starting with `=`, `+`, `-` or `@` get a leading apostrophe to block spreadsheet formulas. A section the user cannot access returns 403; a section without a table (cover, annex) returns 404. Each export writes an audit log entry `management_report.exported` with the user, time, section, table, format, filters and row count.

Only `format=csv` is supported: no spreadsheet library is installed, and none was added. There is no "export all" ZIP for the same reason; each table has its own Export CSV button.

## Permissions

Migration `2026_10_15_000001_grant_management_report_permissions` adds `reports.export` (and `reports.view` if missing) and grants both to the Management, Executive, Management / Executive, Division Head and Administrator roles. **Run `php artisan migrate`** and have users sign in again (or refresh their session) so the new permissions reach the browser. `PermissionSeeder` and `RolePermissionSeeder` include the same permissions for new installations.

`reports.view` already existed and is also held by Administrative Admin. That role can call the report API, but it only receives the sections its other permissions allow. The Reports & Summary tab and sidebar link require `reports.view`; Export CSV buttons appear only with `reports.export`, and the backend enforces both.

## PDF

No PDF library was added. **Print / Save as PDF** opens the browser's print dialog with a print stylesheet: only the report is printed, the cover fills the first page, each section starts on a new page, table headers repeat, and every page has a header (title and period) and footer (generation time, author and data scope). Choose "Save as PDF" as the printer to produce the formal PDF.

## States

The report loads as one request with a loading skeleton, an error with Retry, "No records in your authorised scope" for empty tables, and a Clear filters button when filters produce empty tables. Missing permissions are reported as omitted sections, never as empty tables.
